# R复盘详情刷新状态修复设计

## 目标

修复演示引擎R绩效面板中“更多复盘”展开后，在下一次2秒数据轮询时自动收起的问题。

成功标准：

- 用户展开“更多复盘”后，演示数据继续每2秒刷新，详情区域保持展开。
- 用户主动收起后，后续刷新保持收起。
- 普通交易面板与演示面板继续复用同一套R绩效组件。
- 不修改R计算、交易记录、开仓、止损、止盈或轮询频率。

## 根因

演示页的`fetchDemoData()`每2秒重新生成完整页面HTML，并执行：

```javascript
document.getElementById('main').innerHTML = h;
```

这会销毁当前`<details id="rPerformanceDetails">`节点并创建默认关闭的新节点，因此浏览器原有的`open`状态无法保留。

## 设计

采用页面内存状态保存方案：

1. 增加一个布尔状态，默认值为关闭。
2. 增加独立的状态记录函数，接收`details`节点并保存其`open`值。
3. `details`的`ontoggle`只调用该独立函数，不包含复杂内联逻辑。
4. `rPerformancePanelHtml()`生成节点时，根据保存状态决定是否输出`open`属性。
5. 演示页下一次轮询重建HTML时恢复用户最后一次选择。

该状态只在当前页面生命周期内保存。浏览器整页刷新或新会话仍默认收起，避免永久占用页面空间。

## 备选方案

- 增量更新整个演示面板：可以从根源避免DOM重建，但改动范围大，容易影响持仓卡片、交易分页和净值图，不适合本次单点修复。
- 默认永久展开：实现简单，但用户无法保留收起状态，不符合现有交互。

## 测试

新增前端回归测试，使用真实`rPerformancePanelHtml()`和状态记录函数验证：

1. 初始HTML不包含`open`属性。
2. 模拟用户展开后，下一次重新生成的HTML包含`open`属性。
3. 模拟用户收起后，下一次重新生成的HTML不包含`open`属性。
4. 现有R绩效计算、渲染安全和普通/演示复用测试继续通过。

## 部署与验证

- 只部署`web_ui.py`。
- 部署前备份服务器现有`web_ui.py`。
- 服务器编译通过后重启`macd-bot`；`macd-admin`无需重启。
- 验证服务状态、演示引擎持仓与交易记录数量保持不变。
- 验证展开状态跨至少两次2秒轮询保持，并检查服务器日志无新增异常。
- 部署结果记录到本地`PROGRESS.md`。
