# 动能压缩零候选修复设计

日期：2026-08-24

## 问题与证据

线上完整扫描正常完成 `475` 个 Binance Futures USDT 永续交易对、`950` 个多空评价，耗时约 `15.22s`，网络错误为 `0`，但合格候选和观察池均为 `0`。

逐窗口只读复核确认两个实现缺陷：

1. 已批准规则 G04 只要求窗口内收盘价不位于 EMA8 与 EMA21 之间；当前代码额外要求 LONG 的每根收盘价高于两条 EMA、SHORT 的每根收盘价低于两条 EMA，错误缩小了结构窗口。
2. 没有任何非长度规则全部通过时，窗口选择回退到完整 `220` 根输入，导致所有拒绝结果统一携带 `WINDOW_TOO_LONG` 及整段历史产生的 EMA 原因，无法表达实际最接近窗口的失败原因。

当前行情按 G04 规格原义重放后，满足至少 15 根基础 EMA 窗口的方向由 `6` 增至 `24`，但仍没有方向通过全部枢轴、触碰、摆动和收缩硬门槛。因此本修复恢复规则准确性和可观测性，不承诺当前市场立即产生候选，也不通过放宽研究阈值制造信号。

## 规则修复

### G03 EMA 顺序

- LONG：窗口每根 `EMA8 > EMA21`。
- SHORT：窗口每根 `EMA8 < EMA21`。
- 保持现有硬门槛和拒绝码，不改变阈值。

### G04 收盘不进入 EMA 区

- 每根收盘价不得满足 `min(EMA8, EMA21) <= close <= max(EMA8, EMA21)`。
- LONG 和 SHORT 使用同一“区间外”定义；不额外要求收盘价始终位于方向侧。
- 边界相等视为进入 EMA 区并拒绝。

### 窗口选择失败

- 仍以最后一根已收盘 15m K 线为固定端点，从最长到最短搜索满足全部非长度规则的连续后缀。
- 找到后再应用 `15 <= bars <= 100`，不截断过长窗口。
- 若不存在满足全部非长度规则的后缀，返回实际搜索范围内拒绝原因最少、长度最长的候选后缀；不得回退为完整 220 根历史。
- 若基础 EMA 连续后缀不足 15 根，返回该真实连续后缀并使用长度拒绝原因，不伪造 220 根窗口。
- 诊断候选不能进入观察池；只有拒绝原因为空且长度合规的窗口保持现有入池资格。

## 扫描诊断与页面

- 保留市场扫描报告现有 `rejection_counts`，并在监控器内保存最近一次完整扫描的拒绝分布。
- 内部压缩状态接口在 `scan.rejection_counts` 暴露该分布；服务重启且尚未完成首轮扫描时返回空对象。
- 用户端动能压缩页面显示按次数降序排列的主要拒绝原因；只显示诊断数据，不改变过滤、观察池、突破事件、声音或企业微信投递。
- 不持久化完整的 950 条拒绝记录，避免扩大状态文件和泄露无必要的原始数据。

## 兼容性边界

- 数据源继续为 Binance Futures，成交额门槛继续为 `>= 1,000,000 USDT`。
- 不修改枢轴跨度、触碰容差、触碰次数、收缩比例、EMA 距离、摆动结构、15–100 根窗口、HTF 标签或状态机阈值。
- 不修改交易策略、订单、持仓、数据库、微信配置或推送负载。
- 修复本地扫描服务与 `screener.fetch_klines` 的参数兼容测试，防止未来部署本地新版服务后全市场请求失败。

## 测试与验收

- RED/GREEN 测试证明 LONG/SHORT 的收盘可位于 EMA 区间任一外侧，但位于区间内或等于边界时必须拒绝。
- 测试证明无完整合格后缀时返回真实最接近窗口，不再统一返回 220 根。
- 测试证明满足全部硬门槛的既有候选、观察池身份和突破状态机不变。
- 测试监控器保存最近完整扫描的 `rejection_counts`，内部接口及页面正确显示。
- 测试扫描服务调用真实 `screener.fetch_klines` 支持的参数签名。
- 运行动能压缩专项测试、完整测试集、Python 编译和 `git diff --check`。
- 本地修复完成后单独请求生产部署授权；部署前备份，部署后更新本地 `PROGRESS.md`。
