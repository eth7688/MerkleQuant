# Predicta 震荡过滤拦截开关设计

## 目标

在管理后台的演示引擎设置中增加一个两态开关，让用户可以明确控制 Predicta 信号是否被震荡过滤器硬拦截。

## 行为

- 开启：保存 `predicta_choppy_filter_mode="hard"`，信号K被判定为震荡时直接拒绝进入快速开仓或等待确认池。
- 关闭：保存 `predicta_choppy_filter_mode="off"`，不因震荡判定拦截 Predicta 信号。
- 当前配置为 `hard` 时，页面加载后开关显示开启；其他值均显示关闭。
- 保存后复用现有 `/api/admin/demo/config` 配置接口和热更新链路，不重启服务。
- 开关只影响保存后的新信号，不修改或平掉已有持仓。

## 界面

- 开关放在管理后台“演示引擎设置”的信号源字段附近。
- 标签为“震荡过滤拦截”。
- 开启说明为“震荡信号不进入开仓链路”；关闭说明为“不使用震荡过滤拦截”。
- 沿用现有原生 HTML/CSS/JavaScript 和管理后台组件样式，不引入依赖。

## 数据流

1. 配置接口返回 `predicta_choppy_filter_mode`。
2. 页面将 `hard` 映射为开关开启。
3. 用户保存时将开关布尔值映射为 `hard` 或 `off`。
4. `BotManager.save_user_config()` 原位合并配置并保护已有 API 密钥。
5. 运行中的演示 Bot 热更新 `cfg`，后续 `_predicta_choppy_filter_state()` 使用新模式。

## 安全边界

- 不修改 RJ 过滤配置。
- 不覆盖测试网 API Key/Secret、仓位、风险、止损或出场参数。
- 不把 `log_only` 暴露为本次两态开关；若服务器历史配置为 `log_only`，页面按关闭显示，只有用户主动保存时才写为 `off`。

## 验证

- 静态测试确认管理后台包含开关、回显映射和保存映射。
- 后端测试确认 `hard` 拦截震荡信号、`off` 放行同一信号。
- 完整单元测试和 Python 编译通过。
- 部署后通过配置接口验证开关为开启，保存切换不丢失测试网 API 凭证。
