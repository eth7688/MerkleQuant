# 动能压缩交易对复制按钮设计

## 目标

在动能压缩页面所有实际候选与事件表格的交易对前增加现有样式的复制按钮，让用户一次点击即可复制完整交易对，例如 `BTCUSDT`。

## 范围

复制按钮覆盖：

- `LONG 观察池`
- `SHORT 观察池`
- `当前突破`
- `终止结构`

扫描失败明细不属于候选或事件记录，本次不增加复制按钮。其他页面和交易执行逻辑不变。

## 交互与视觉

- 复用现有 `.copy-sym` 双页图标和 `copySymbol()` 函数，不新增前端依赖或复制列。
- 图标位于交易对文字前，保持表格宽度、列数和现有响应式布局。
- 点击后复制原始完整 `symbol` 值；页面继续按现有格式显示交易对。
- 复制成功后沿用现有 `copied` 状态，图标短暂显示品牌色反馈。
- 点击复制按钮不得触发行点击或其他页面行为。

## 安全与数据流

- 每个渲染函数先把原始 `symbol` 规范化为字符串。
- 通过经过现有 HTML 转义函数处理的 `data-symbol` 属性传递复制值，再由按钮读取该属性调用 `copySymbol()`。
- 不把未转义的交易对直接拼接进 JavaScript 字符串，避免引号或特殊字符破坏 HTML/事件属性。
- 渲染不得修改输入 payload、观察池行或事件行。

## 实现边界

- 仅修改 `web_ui.py` 中动能压缩表格的交易对单元格渲染。
- 复用现有 CSS 与复制函数，不修改后端 API、状态文件、扫描规则、微信、声音、交易或权限逻辑。
- 不改变表头、列数、DOM 容器 ID 或现有数据绑定。

## 验证

- 渲染测试确认 LONG/SHORT 观察池、当前突破和终止结构的交易对前均包含复制按钮。
- 断言按钮保存并复制完整交易对，而不是页面展示用的缩写。
- 使用包含引号与 HTML 特殊字符的测试值验证属性转义。
- 连续两次渲染同一 payload，输出保持一致且输入数据不变。
- 运行相关动能压缩集成测试、完整测试套件、`web_ui.py` 编译和 `git diff --check`。

## 验收标准

用户在上述四个区域点击交易对前的图标后，可以复制完整交易对；按钮外观和反馈与系统其他页面一致，不影响原表格布局、刷新、声音、微信或扫描功能。
