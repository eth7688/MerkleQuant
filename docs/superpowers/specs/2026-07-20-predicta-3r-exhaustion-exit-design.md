# Predicta 3R衰竭减仓与趋势尾仓设计

## 1. 目标

在不牺牲主要趋势机会的前提下，提高Predicta/EWO仓位在无法推进到3R时的利润兑现率，并让真正达到3R的仓位继续保留趋势尾仓。

本设计不试图预测某笔交易是否一定到不了3R。系统只依据持仓后的已收盘K线，识别动能反转、推进停滞和结构破坏是否同时出现。只有三项全部成立时，才执行一次提前减仓。

盈利优势不能由规则本身保证，最终必须通过同口径逐K回测和演示引擎样本验证。

## 2. 范围与边界

- 仅用于Predicta/EWO开仓策略。
- 第一阶段仅植入演示引擎和纸面回测，不改变普通用户策略。
- 不改变Predicta开仓条件、震荡过滤、初始止损计算和现有最大持仓限制。
- 不增加固定5R或8R止盈。
- Predicta仓位不增加时间止损。
- 部署后新开的仓位使用`exit_profile_version=2`。
- 部署时已有仓位继续使用`exit_profile_version=1`的旧出场链路，直至自然结束。

## 3. 固定R口径

新版仓位在真实开仓成交确认后固定以下基准：

- `original_quantity`：首次真实成交数量。
- `initial_risk_per_unit = abs(fill_entry_price - initial_sl)`。
- `initial_risk_usdt = initial_risk_per_unit * original_quantity`。

整个仓位生命周期内，价格R统一按真实成交价和`initial_risk_per_unit`计算。减仓、交易所仓位同步和剩余数量变化不得重置R基准。分段盈亏统计最终按同一个原始仓位汇总。

## 4. V2出场状态机

### 4.1 初始保护

1. 低于0.8R：保持初始结构止损，不运行衰竭检测或ATR追踪。
2. 首次达到0.8R：止损推至入场价，保留现有三轮止损冷却机制。
3. 首次达到1.2R：止损锁定0.2R，仓位进入`exhaustion_armed`阶段，但不启动ATR追踪。

`exhaustion_armed`表示历史上已经达到1.2R。此后即使当前R因回撤低于1.2R，衰竭检测仍可运行；否则0.5R回撤条件会与激活条件产生互斥。

### 4.2 3R前硬衰竭减仓

在仓位已经进入`exhaustion_armed`、尚未实时成交3R减仓、且尚未执行过衰竭减仓时，系统在每根新收盘K线上计算三类证据：

1. **动能反转**
   - 多单：EWO收盘值小于或等于0。
   - 空单：EWO收盘值严格大于0。
   - EWO使用与开仓一致的SMA5减SMA35，只读取已收盘K线。柱体仅缩短不构成动能反转。

2. **推进停滞并明显回撤**
   - 以最近三根已收盘K线开始前的MFE为基准。
   - 三根K线内的最佳顺势价格未把基准MFE提高至少0.1R。
   - 最新收盘价相对仓位生命周期MFE回撤至少0.5R。
   - 两个子条件必须同时成立。

3. **结构破坏**
   - 使用开仓周期上、入场后形成的最近一个严格确认分型。
   - 多单：最新收盘价跌破最近确认底分型的原始低点。
   - 空单：最新收盘价突破最近确认顶分型的原始高点。
   - 如果入场后尚无有效确认分型，结构破坏为`false`。

只有三项证据全部为`true`时，系统执行一次硬衰竭减仓：

- 平掉`original_quantity`的50%，受交易所数量精度约束。
- 成功后将`exhaustion_partial_triggered`置为`true`。
- 剩余仓位止损优先锁到1R；若原止损更优则保持原止损。
- 如果当前价格已经回落到1R保护价错误一侧，不追价、不挂无效止损，保持当前有效止损并记录`one_r_lock_skipped`。
- 只有一项或两项证据成立时，仅记录判定结果，不减仓、不移动止损。

硬衰竭减仓后，系统不再重复运行该减仓动作，剩余仓位继续等待3R。

### 4.3 3R减仓和趋势尾仓

实时标记价达到3R时，3R动作优先于同轮硬衰竭检测：

- 未发生硬衰竭减仓：平掉当前仓位80%，保留原始仓位20%。
- 已发生硬衰竭减仓：平掉当前剩余仓位80%，保留原始仓位约10%。
- 3R减仓成功后将`target_3r_triggered`置为`true`。
- 尾仓止损立即锁到2R。
- 从3R减仓成功后才启动`ATR(14) × 3.5`吊灯追踪。
- 尾仓有效止损取2R硬保护线与ATR吊灯线中更有利的一条，并且只能向盈利方向移动。
- 尾仓不设置固定5R或8R目标，最终由止损或ATR吊灯退出。

理论整笔R示例，不计手续费、滑点和数量取整：

- 无衰竭减仓，尾仓在2R退出：`0.8 × 3R + 0.2 × 2R = 2.8R`。
- 无衰竭减仓，尾仓在5R退出：`0.8 × 3R + 0.2 × 5R = 3.4R`。
- 在`xR`发生衰竭减仓且剩余仓位最终在1R止损：`0.5 × xR + 0.5 × 1R`。
- 衰竭后恢复到3R时，最终尾仓约为原仓10%，因此收益按实际三段成交汇总。

### 4.4 同轮事件优先级

从高到低：

1. 交易所确认仓位不存在或止损已经成交。
2. 实时标记价达到3R并执行3R减仓。
3. 0.8R与1.2R保护动作。
4. 新收盘K线的硬衰竭检测。
5. 3R减仓后的ATR吊灯更新。

优先级保证同一轮既触及3R又出现衰竭证据时，只执行3R路径。

### 4.5 70/30双速尾仓实验

在V2的80/20规则之外，新增一个仅用于逐K回放的实验退出档案。实验档案不得改变演示引擎、真实订单、持仓持久化或管理后台配置；只有通过第10节的晋级标准并再次取得部署批准后，才允许另行设计实盘接入。

回放必须使用完全相同的开仓、初始止损、0.8R保本、1.2R锁0.2R和3R前硬衰竭逻辑，只替换3R之后的仓位分配：

- A组基线`v2_80_20`：3R平当前仓位80%，剩余20%使用2R硬保护与`ATR(14) × 3.5`追踪。
- B组实验`v2_70_30_donchian_{20|40|60}`：3R平当前仓位70%，剩余30%等分为中速和慢速两个虚拟尾仓。
- 中速尾仓占3R时当前仓位15%，使用2R硬保护与`ATR(14) × 3.5`追踪。
- 慢速尾仓占3R时当前仓位15%，使用2R硬保护与指定周期的Donchian中轨追踪。
- Donchian中轨只读取已收盘K线，计算式为`(N根滚动最高价 + N根滚动最低价) / 2`，候选周期仅为20、40、60根。
- 多单的慢速止损取历史有效止损与最新Donchian中轨中更高者；空单取更低者。止损只允许向盈利方向移动。
- 两个虚拟尾仓都不设置5R、8R或其他固定止盈。

若3R前已经执行硬衰竭减仓，3R时仍按“当前剩余仓位”的70%兑现。此时保留原始仓位15%，中速和慢速虚拟尾仓各占原始仓位7.5%。回放使用精确小数数量，不模拟碎仓；未来若批准接入演示引擎，必须重新设计交易所数量取整与`minQty`降级行为。

理论整笔R示例，不计手续费、滑点和数量取整：

- A组尾仓在2R退出：`0.8 × 3R + 0.2 × 2R = 2.8R`。
- B组两个尾仓都在2R退出：`0.7 × 3R + 0.3 × 2R = 2.7R`。
- A组尾仓在6R退出：`0.8 × 3R + 0.2 × 6R = 3.6R`。
- B组两个尾仓等效在6R退出：`0.7 × 3R + 0.3 × 6R = 3.9R`。

实验不得使用ADX、RSI、Predicta评分或其他信号动态改变70/30比例，避免把开仓过滤与3R后的收益分配耦合。

## 5. 持久化状态

新版仓位至少保存：

- `exit_profile_version`
- `original_quantity`
- `initial_risk_per_unit`
- `initial_risk_usdt`
- `exhaustion_armed`
- `exhaustion_partial_triggered`
- `exhaustion_partial_quantity`
- `target_3r_triggered`
- `target_3r_partial_quantity`
- `exhaustion_last_bar_time`
- `highest_price`
- `lowest_price`
- `current_sl`
- 现有止损单ID和其他恢复字段

重启恢复必须以版本、交易所真实剩余数量和阶段标记共同决定下一动作。同一根收盘K线不得重复计算或重复发单。

## 6. 订单与异常处理

- 只有减仓订单确认成功且交易所剩余仓位同步成功后，才写入对应阶段完成标记和实际成交数量。
- 订单失败时不改变本地数量与阶段状态，下一轮允许幂等重试。
- 减仓成功后，按交易所真实余量撤销旧止损并补挂新止损。
- 止损补挂失败必须记录错误并重试，不得伪造成功状态。
- 数量统一经过交易所步长向下取整。
- 如果目标尾仓低于`minQty`或无法形成有效订单，则平掉该阶段全部剩余仓位，不保留无效碎仓。
- 所有数量继续使用现有交易所兼容格式，不使用会破坏精度的字符串去零方式。
- K线不足、行情接口失败或无有效分型时，硬衰竭判定失败关闭，不猜测、不减仓。

## 7. 可观测性

每次硬衰竭检查记录：

- symbol、direction、interval、signal_key
- closed_bar_time
- current_r、mfe_r、drawdown_from_mfe_r
- ewo_value、ewo_reversed
- stagnation_bars、mfe_improvement_r、progress_stalled
- fractal_type、fractal_price、structure_broken
- 三项证据总数和最终动作

每次部分平仓记录订单响应、计划数量、实际数量、平仓前后交易所数量、阶段版本和新的保护止损。前端统计按原始仓位聚合，不把分段成交计为多笔交易。

## 8. 配置

V2内部参数采用以下默认值：

- `tier1_defense_r = 1.2`
- `exhaustion_stagnation_bars = 3`
- `exhaustion_min_mfe_improvement_r = 0.1`
- `exhaustion_min_drawdown_r = 0.5`
- `exhaustion_partial_fraction = 0.5`
- `exhaustion_remaining_lock_r = 1.0`
- `target_3r = 3.0`
- `target_3r_close_fraction = 0.8`
- `runner_floor_r = 2.0`
- `atr_trail_period = 14`
- `atr_trail_mult = 3.5`

回放实验使用固定参数：

- `experiment_profiles = ["v2_80_20", "v2_70_30_donchian_20", "v2_70_30_donchian_40", "v2_70_30_donchian_60"]`
- `experimental_target_3r_close_fraction = 0.7`
- `experimental_medium_runner_fraction = 0.15`
- `experimental_slow_runner_fraction = 0.15`
- `experimental_donchian_periods = [20, 40, 60]`

第一阶段不新增管理后台控件，避免在样本不足时频繁调参。参数保留在策略配置层，待演示数据验证后再决定是否开放。

## 9. 测试要求

自动化测试至少覆盖：

1. 多空方向完全对称。
2. 0.8R、1.2R、3R阈值边界。
3. 未达到1.2R时不运行硬衰竭检测。
4. EWO、停滞回撤、结构破坏分别缺一项时不减仓，三项全部成立才减仓。
5. 仅使用已收盘K线，忽略正在形成的K线。
6. 同轮满足3R和衰竭条件时只执行3R路径。
7. 普通路径最终保留原仓20%，衰竭后恢复路径最终保留原仓约10%。
8. 1R或2R止损位处于当前价格错误一侧时不挂无效订单。
9. 市价订单失败、数量取整、无效碎仓和止损补挂失败。
10. 重启恢复后不重复执行两个部分止盈阶段。
11. `exit_profile_version=1`仓位完全沿用旧逻辑。
12. 分段成交按原始仓位聚合计算胜率、平均R和盈亏。
13. A组80/20和三个B组70/30档案共享完全相同的入场与3R前事件序列。
14. B组在3R后准确形成15%中速与15%慢速虚拟尾仓；硬衰竭后分别为原始仓位7.5%。
15. Donchian 20、40、60只读取已收盘K线，并对多空方向执行单向收紧。
16. A/B统计计入相同的手续费与滑点，所有分段退出按原始仓位聚合为一笔交易。
17. 回放实验不会写入演示配置、演示持仓或发出任何交易所订单。

完成代码后必须运行项目完整测试集与Python编译检查。

## 10. 演示部署与验收

1. 本地测试通过后更新本地文件。
2. 部署前备份服务器待替换文件、演示配置和持仓状态。
3. 仅为演示引擎的新仓位启用V2，现有仓位保持V1。
4. 重启相关服务并验证服务状态、配置、持仓连续性、止损单和事件日志。
5. 部署完成后更新`PROGRESS.md`，记录修改内容、部署文件、备份路径和验证结果。
6. 先使用逐K回放比较A组和三个B组：整笔平均R、盈利因子、最大回撤、3R到达率、5R以上交易的收益贡献、硬衰竭触发率、触发后恢复到3R的比例和MFE回吐比例。
7. 数据必须按时间顺序切为至少三个互不重叠的走步区间；每个档案使用相同K线、信号、手续费和滑点口径，不允许依据测试区间结果反向调整参数。
8. 若聚合完成交易少于100笔，只报告观察结果，不执行实验档案晋级。
9. B组档案只有同时满足以下条件才取得“可申请演示部署”资格：样本外整笔平均R高于A组、样本外盈利因子高于A组、至少两个走步区间的整笔平均R高于A组，并且样本外最大回撤相对A组的恶化不超过10%。最大回撤相对恶化率定义为`(abs(B组最大回撤) - abs(A组最大回撤)) / abs(A组最大回撤)`；若A组最大回撤为0，则B组最大回撤也必须为0。
10. 多个B组同时合格时，先选择样本外平均R最高者；若相同，再选择最大回撤较小者。选择结果只形成报告，不自动修改演示引擎。
11. 任何实验档案接入演示引擎前，必须再次取得用户批准，并补充交易所数量精度、真实订单、持久化与重启恢复设计。

在获得足够同口径样本前，只报告观测结果，不宣称V2或70/30双速尾仓必然提高盈利。
