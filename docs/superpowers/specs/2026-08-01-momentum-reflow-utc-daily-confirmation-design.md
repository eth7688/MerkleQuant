# 动能回流 UTC 日线确认设计

## 目标

让动能回流扫描器的日线确认与 TradingView 的 Bitget 永续合约日线一致，使用 UTC 00:00 切日的 `1Dutc` K 线，消除相同交易所因日线边界不同产生的形态差异。

## 范围

- 仅修改 `momentum_reflow.py` 中动能回流候选的 Bitget 日线请求。
- 1H 突破、扩张、首次回流和五根窗口状态机保持不变。
- `screener.py` 的全局 `"1d" -> "1D"` 映射保持不变，避免影响其他策略和页面。
- 页面字段、持久化格式和已有信号键保持不变。

## 方案

为 `fetch_klines` 增加可选的 Bitget 粒度覆盖参数，默认不传时继续使用现有区间映射。动能回流请求 40 根日 K 时显式传入 `granularity="1Dutc"`。这样改动边界清晰，其他调用者不发生行为变化。

不采用全局修改日线映射，因为这会改变所有 Bitget 日线消费者；也不在动能回流模块复制一套 HTTP 请求，因为会绕过现有的已收盘过滤、错误处理和数据结构转换。

## 数据流

1. 1H 状态机生成回流候选。
2. 动能回流模块通过公共 K 线抓取函数请求 Bitget `1Dutc`。
3. 公共抓取函数继续执行 `closed_only=True` 过滤，排除当前未收盘 UTC 日 K。
4. `daily_confirmation` 使用最后两根已收盘 UTC 日 K 判定吞没等形态。
5. 通过确认的候选按现有格式进入当日面板。

## 验证

- 回归测试证明动能回流日线请求使用 `1Dutc`，而普通 Bitget `1d` 请求仍使用 `1D`。
- 现有动能回流测试完整通过。
- TRXUSDT 重放应不再把北京时间边界下的 2026-07-31 K 识别为 TV 日线看跌吞没。
- INUSDT 使用同一 UTC 日线边界重放，确认结果与 Bitget `1Dutc` 原始数据一致。
- 运行 Python 编译检查和完整项目测试。
