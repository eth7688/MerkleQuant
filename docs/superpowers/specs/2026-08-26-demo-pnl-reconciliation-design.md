# 演示引擎盈亏记录修复设计

## 背景

演示引擎当前同时展示两套口径：

- 账户权益口径来自币安合约测试网的实时账户权益；
- 交易记录口径来自 `trades_<uid>.jsonl` 中保存的单笔盈亏。

只读核对发现，账户权益数据可以与交易所接口对应，但现有 282 条历史成交全部使用估算盈亏，没有保存币安真实已实现盈亏。历史加载去重键还会把同一秒发生、盈亏相同的合法减仓与最终平仓误判为重复记录。修复目标是让部署后的新交易使用可审计的交易所成交结果，同时保留历史估算记录，不伪造历史回填。

## 范围

本次修改包括：

1. 币安合约平仓后按平仓订单查询真实成交明细；
2. 保存真实成交均价、已实现盈亏、平仓手续费和数据来源；
3. 面板统计优先使用可用的交易所净收益；
4. 为新成交记录生成唯一标识；
5. 修正历史记录加载去重规则，保留同秒减仓和最终平仓；
6. 增加相应的后端与面板统计回归测试。

本次不包括：

- 不修改历史估算盈亏；
- 不尝试把交易所历史收益流水强行匹配到 282 条旧记录；
- 不清空、归档或重建现有交易记录；
- 不把账户级资金费强行分摊到单笔成交；
- 不改变策略入场、出场、仓位或风控规则。

## 数据口径

### 账户权益

账户权益继续作为真实总业绩的权威口径。它包含钱包余额、未实现盈亏、手续费和资金费产生的最终账户变化。

### 新交易记录

币安平仓成功后，系统使用平仓订单号查询该订单的全部成交：

- `exit`：按成交数量加权的实际平仓均价；
- `exchange_pnl`：各成交的 `realizedPnl` 合计；
- `exchange_fee`：各成交手续费合计；
- `exchange_net_profit`：`exchange_pnl - exchange_fee`；
- `pnl_source`：成功时记录为币安订单成交来源；
- `exit_price_source`：成功时记录为订单成交价。

交易记录统计优先级为：

1. `exchange_net_profit`；
2. `exchange_pnl`；
3. 原有 `pnl` 估算值。

资金费属于持仓期间的账户级流水，减仓与最终平仓可能共享同一持仓周期。为避免重复归属，本次不写入单笔交易净收益，而由账户权益和账差继续完整反映。

### 查询失败降级

如果币安成交明细暂时不可用，平仓流程不得失败或重复下单。系统保留已有估算结果，并明确写入估算来源。估算值不得标记为交易所真实值。

## 币安成交解析

在 `BinanceClient` 增加与现有 Bitget `resolve_close_trade` 对齐的只读解析能力：

1. 从平仓响应取得订单号；
2. 调用币安合约用户成交接口，并按交易对和订单号限定结果；
3. 汇总多笔部分成交的数量、成交额、已实现盈亏和手续费；
4. 返回统一的 `exit_price`、`exchange_pnl`、`exchange_fee`、`exchange_net_profit` 和 `pnl_source`；
5. 成交尚未落库时进行有上限的短暂重试，超过上限后返回空结果并使用估算降级。

查询是只读操作，不改变订单状态。不得为了获取成交结果再次提交、取消或修改订单。

## 记录唯一性与历史兼容

### 新记录

每次 `_append_trade` 在缺少 `record_id` 时生成唯一标识，并将其同时写入内存和 JSONL 文件。减仓、最终平仓及其他成交事件各自拥有独立标识。

### 历史记录

历史记录没有 `record_id`，加载时使用以下字段组成兼容去重键：

- 时间；
- 交易对；
- 方向；
- 原因；
- 数量；
- 盈亏；
- 信号键。

该规则能够保留 PENGU 同秒发生的“二阶减仓50%”与“击穿动态追踪防线”两条合法记录，同时仍过滤真正完全相同的历史重复行。

不重写原始 `trades_<uid>.jsonl`。修复只改变加载结果和以后追加的记录格式，因而可以回滚代码而不破坏历史文件。

## 面板行为

面板继续同时显示：

- 已实现盈亏；
- 持仓浮动；
- 记录净盈；
- 今日权益；
- 权益净盈；
- 账差。

新交易存在 `exchange_net_profit` 时，已实现盈亏、记录净盈、今日记录盈亏和胜率统一使用交易所净收益。旧交易继续显示“估算”来源。账户权益和今日权益的算法不变。

胜率仍按交易记录行统计；减仓和最终平仓是两个独立成交事件。此次不改变胜率定义，避免扩大修复范围。

## 测试

回归测试至少覆盖：

1. 同一秒、同一交易对、同方向、同盈亏但原因不同的两条历史记录均被加载；
2. 完全相同的历史重复行仍只加载一次；
3. 新记录自动获得不同的 `record_id`，重启后均可恢复；
4. 币安一个平仓订单包含多笔成交时，成交均价、已实现盈亏和手续费正确汇总；
5. 交易所净收益优先于交易所毛收益和估算值；
6. 查询失败时保留估算值并标注估算来源；
7. 快速摘要与完整摘要使用相同的已实现盈亏、记录净盈、今日盈亏和胜率口径；
8. 原有 Bitget 真实盈亏记录保持兼容。

## 验收标准

- PENGU 两条合法历史记录不再因重启少计 351.50 USDT；
- 部署后的币安新平仓记录在成交明细可用时包含真实成交字段；
- 交易记录统计优先采用交易所净收益；
- 查询失败不影响平仓完成，且不会把估算值伪装为真实值；
- 现有测试与新增回归测试全部通过；
- 不修改历史文件、账户配置、策略规则或生产交易状态。
